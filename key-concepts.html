Seven key concepts

Use these explanations as a quick reference while reading the two lessons.

The vocabulary of an exchange

1. Client and server

A client initiates a request, and a server answers it. In a page load, the browser acts as a client. Proxies can forward exchanges between the browser and origin server.

Example: a browser requests a lesson from a web server.

2. Resource and URL

A resource is something an HTTP request identifies, such as a lesson, image, or application record. A URL provides an address, including a scheme, host, and path.

Example: https://example.org/lessons identifies a resource; the server may generate its representation dynamically.

3. Method

The method states the action requested by the client. Methods have defined semantics that remain recognizable across HTTP versions.

Example: GET retrieves a representation, while POST submits content for processing.

4. Status code

A three-digit code communicates the result of handling a request. Its first digit identifies the broad outcome class.

Example: 201 reports creation; 503 reports temporary service unavailability.

5. Header field

A header field carries metadata or instructions about a message. Fields can describe format, caching, authentication, and other behavior.

Example: Content-Type: application/json identifies JSON content.

6. Caching

A cache stores responses for possible reuse. Freshness and validation rules determine when a stored response may satisfy a later request.

Example: Cache-Control: max-age=600 establishes a 600-second freshness lifetime.

7. HTTPS

HTTPS protects HTTP communication using a secure transport. It helps provide confidentiality, integrity, and server authentication. It does not by itself establish that a site’s content is trustworthy.

Example: a sign-in page uses HTTPS to protect data in transit; the application still needs authorization checks.

Sources: [4], [5], [9].

Related example: cookies and sessions

HTTP is stateless. Applications can maintain continuity across requests through mechanisms such as cookies. A server can set a session cookie, and the browser sends that cookie on later eligible requests.

Secure limits cookie transmission to secure channels. HttpOnly prevents access through common browser scripting APIs. The application must still check the session’s validity and access permissions.

Sources: [10].
